Your system as a recipe.

nomira builds an immutable Linux from a recipe: Arch packages, ordinary configuration files and atomic updates.

Early stage of development (alpha): for trying out, not yet for systems you depend on.

From recipe to running system

Phases run one after another. The groups of a phase run at the same time, and the build checks that they do not get in each other's way.

  1. 1RecipeA YAML file lists the steps that build the system.
  2. 2PhasesStep by step, in a fixed order.
  3. 3GroupsIndependent, at the same time, cached one by one.
    • terminal
    • network
    • boot
  4. 4CheckIf two groups write the same file, the build aborts.
  5. 5ImageA finished, immutable system image.
  6. 6Switchbootc switches atomically. The old state stays as a way back.

What you get

  • Built from a recipe

    A recipe is a list of ordinary commands, not a declarative language. But every build starts over from the base image, so nothing lingers from earlier.

  • Immutable

    The running system is read-only. Updates arrive completely or not at all, with a way back.

  • Freely configurable

    Any command and normal files in /etc. No language of its own that has to know every option.

  • Plain Arch packages

    Packages come unchanged from Arch Linux, in the usual paths. Most of what the Arch Wiki says still applies.

Three parts

  • Frontend

    Translates the recipe for BuildKit: groups build in parallel, and each build verifies that they are independent. It stands on its own and builds any container image.

    About the frontend

  • CLI

    One command builds, checks and switches the system: nomira switch.

    CLI docs

  • Base image

    The smallest Arch Linux that bootc can boot, with AppArmor. Your recipe chooses everything else.
