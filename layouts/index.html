Dein System als Recipe.

nomira baut ein unveränderliches Linux aus einer deklarativen Beschreibung: mit Arch-Paketen, gewöhnlichen Konfigurationsdateien und atomaren Updates.

Vom Recipe zum laufenden System

Phasen laufen nacheinander. Die Gruppen einer Phase laufen gleichzeitig, und der Build prüft, dass sie sich nicht in die Quere kommen.

  1. 1RecipeEine YAML-Datei beschreibt das System.
  2. 2PhasenSchritt für Schritt, in fester Reihenfolge.
  3. 3GruppenUnabhängig, gleichzeitig, einzeln im Cache.
    • terminal
    • netzwerk
    • boot
  4. 4PrüfungSchreiben zwei Gruppen dieselbe Datei, bricht der Build ab.
  5. 5ImageEin fertiges, unveränderliches System-Image.
  6. 6Umstellenbootc wechselt atomar. Der alte Stand bleibt als Rückweg.

Wofür nomira gedacht ist

  • Deklarativ

    Das Recipe ist das System. Was nicht drinsteht, ist nicht drauf.

  • Unveränderlich

    Das laufende System ist schreibgeschützt. Updates kommen ganz oder gar nicht, mit Rückweg.

  • Frei konfigurierbar

    Beliebige Befehle und normale Dateien in /etc. Keine eigene Sprache, die jede Option kennen muss.

  • Geprüft parallel

    Eine geänderte Gruppe baut nur sich selbst neu. Dass Gruppen unabhängig sind, wird bei jedem Build nachgewiesen.

Drei Bausteine

  • Frontend

    Übersetzt das Recipe für BuildKit. Es steht für sich und baut jedes Container-Image, nicht nur Betriebssysteme.

    Das Frontend einzeln nutzen

  • CLI

    Ein Befehl baut, prüft und stellt das System um: nomira switch.

  • Basis-Image

    Das kleinste Arch Linux, das bootc starten kann, mit AppArmor. Alles Weitere wählt dein Recipe.

Ehrlich gesagt

Welche Systeme?

Das Frontend ist nicht an eine Distribution gebunden. Als Basis kommt grundsätzlich jedes System infrage, das bootc unterstützt.

Unterstützt und erprobt wird derzeit nur Arch Linux.

Kein Ersatz für NixOS

NixOS prüft mehr, reproduziert genauer und ist viel reifer. nomira verfolgt andere Ziele: vertraute Pakete und Dateien statt einer eigenen Sprache.
